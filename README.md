# 临时聊天室 · wechat-ntr

一个仿微信聊天界面的、**无需注册 / 无历史记录 / 纯前端部署**的临时聊天室。

项目只有一个可直接部署的 `index.html`：浏览器通过公共 MQTT WebSocket 服务交换消息，聊天内容在发送前加密；图片和文件以原始字节分块传输，接收完成后通过 SHA-256 校验完整性。

> 这个项目更适合临时、低敏感度交流和前端实验。当前房间密钥由本地时间推导，**不应把它当作经过安全审计的私密通信工具**。

## 特性

- 微信风格的移动端优先聊天界面，分组展示会话说明
- 附件卡片集中展示大文件提醒与传输状态，提示清晰、不阻断操作
- 无账号、无注册、无应用后端
- 按小时自动进入临时房间
- 文本消息通过 CryptoJS AES 加密后发送
- MQTT 断线自动重连，并明确展示连接状态
- 不加载历史消息；QoS 0，不使用 retained message
- 昵称只保存在当前标签页的 `sessionStorage`
- Enter 发送、Shift + Enter 换行，兼容中文输入法 composition
- 使用 DOM API / `textContent` 渲染用户内容，避免直接插入不可信 HTML
- 图片与文件均保持**原始字节不变**
- 单个附件建议不超过 **5 MiB（约 5 MB）**，允许更大的文件
- 附件按 **8 KiB** 分块传输，可请求缺失分块
- 接收后进行 **SHA-256** 完整性校验，通过后才开放下载
- PNG / JPEG / GIF / WebP 可在聊天中预览，下载仍为原始文件
- 不设固定附件大小或总字节数上限；实际容量受设备内存和浏览器限制
- 单个 HTML 文件即可部署到 Cloudflare Pages、GitHub Pages 或任意静态站点

## 快速使用

1. 打开页面，输入昵称进入聊天室。
2. 双方在同一本地小时加入，并保持设备时间与时区一致。
3. 点击「＋」选择图片或文件；对方点击「接收原文件」开始传输。
4. 保持双方页面在线，完整性校验通过后下载。

附件建议不超过 **5 MiB**，更大的文件仍可传输。超过建议大小时，附件卡片会显示提醒，不会直接拒绝；实际传输能力取决于设备内存、浏览器和公共消息服务。

## 工作原理

文本消息流程：

```text
浏览器 A
  │
  │  roomKey = 本地时间 YYYYMMDDHH
  │  topic   = chat/MD5(roomKey)
  │  payload = AES(JSON, roomKey)
  ▼
公共 MQTT Broker (WSS)
  │
  ▼
浏览器 B
```

当前 MQTT Broker：

```text
wss://broker.emqx.io:8084/mqtt
```

MQTT.js 会在浏览器中从以下 CDN 动态加载：

- jsDelivr
- unpkg

CryptoJS 已直接内联在 `index.html` 中。

### 房间规则

加入聊天室时，页面按设备的**本地年月日小时**生成：

```text
YYYYMMDDHH
```

例如本地时间为 2026-09-21 14:37，则房间时段为：

```text
2026092114
```

随后使用：

```text
chat/MD5(2026092114)
```

作为 MQTT topic，并使用同一个 `roomKey` 作为 CryptoJS AES 的 passphrase。

因此：

- 双方设备时间和时区需要一致，才能自动进入同一个房间。
- 跨小时后，已经加入的页面仍留在原房间。
- 退出后重新加入，才会进入新的小时房间。
- 断线重连仍回到加入时的房间。
- 断线期间的消息不会补发。

## 附件传输

附件协议使用独立 topic：

```text
<chat-topic>/files/v1
```

流程大致如下：

1. 发送端读取原始文件字节并计算 SHA-256。
2. 发送端广播附件元信息，不主动一次性推送整个文件。
3. 接收端点击“接收原文件”后，请求缺失分块。
4. 发送端按请求发送 8 KiB 分块。
5. 接收端重组原始字节并再次计算 SHA-256。
6. 摘要一致时才提供“下载原文件”。
7. 如果校验失败，则不会把不完整或被修改的内容当作成功文件。

当前建议与限制：

| 项目 | 当前值 |
| --- | --- |
| 单个附件建议大小 | 不超过 5 MiB，超出仅提示，仍可传输 |
| 分块大小 | 8 KiB |
| 页面附件内存 | 不设固定字节数上限，受设备内存和浏览器限制 |
| 同时保留的附件项 | 最多 40 个 |
| 每轮请求缺失分块 | 最多 4 个 |
| 图片预览 | PNG / JPEG / GIF / WebP |
| 传输要求 | 发送方与接收方需要同时在线 |

大文件会显示风险提示，但不会因为超过 5 MiB 或页面附件合计超过 30 MiB 而拒绝发送或接收。大文件可能耗时较长、占用较多内存或传输不完整；校验通过前不会开放下载。建议及时移除不需要的附件以释放内存。

双方需要更新页面：旧版本仍会忽略超过 5 MiB 的附件通知。分块大小、请求批次和附件协议保持不变。

附件不会压缩、缩放或重新编码。文件系统层面的创建时间、下载时间等属性可能变化，但下载内容的字节应与发送前一致；页面使用 SHA-256 对这一点进行校验。

## 安全与隐私说明

这个项目有加密，但当前设计的目标是“临时聊天实验”，而不是高安全等级通信。

需要特别注意：

- 房间密钥直接由 `YYYYMMDDHH` 推导，可预测。
- MQTT topic 也由同一时间值计算，因此了解实现的人可以枚举当前时段的房间。
- 没有账号体系、成员认证或可信身份校验，昵称不能证明真实身份。
- 当前消息没有额外的数字签名/身份签名机制。
- 使用的是公共 MQTT Broker，服务可用性、流量限制和运营策略不由本项目控制。
- 项目没有经过正式的密码学或安全审计。

因此，请不要通过本项目发送密码、密钥、身份证件、财务资料、商业机密或其他高敏感信息。

更完整的安全说明与漏洞反馈方式见 [SECURITY.md](SECURITY.md)。

## 本地运行

这是纯静态项目，没有构建步骤。

最简单的方式是直接打开 `index.html`。如果浏览器或安全策略限制本地文件加载，也可以启动任意静态 HTTP 服务，例如：

```bash
python -m http.server 8080
```

然后访问：

```text
http://localhost:8080/
```

## 部署到 Cloudflare Pages

仓库本身就是可部署产物，不需要编译。

如果 Cloudflare Pages 已连接这个 GitHub 仓库：

1. 将生产分支设为 `main`。
2. 不需要构建命令。
3. 让部署结果直接使用仓库根目录中的 `index.html`。
4. 后续向 `main` push 后，由 Cloudflare Pages 自动创建新部署。

如果你使用其他静态托管服务，同样只需要把仓库根目录作为站点目录发布。

## 开发约定

当前项目刻意保持“单文件部署”的形态。修改时建议继续保持：

- 不引入必须运行的后端服务。
- 不把用户消息直接写入 `innerHTML`。
- 修改房间密钥、topic、消息 JSON 或附件协议时考虑旧版本兼容。
- 附件下载前必须先完成完整性校验。
- 发送成功与“对方已经收到”是两个不同概念；不要仅凭本地 socket 写入就显示已送达。

具体见 [CONTRIBUTING.md](CONTRIBUTING.md)。
